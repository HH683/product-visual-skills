# 产品视觉技能 · Product Visual Skills

两个可单独安装、也可连续使用的 Codex 技能：一张产品图生成六张独立视图，再根据参考海报制作产品宣传图。

## 选择要安装的技能

| 技能 | 输入 | 输出 | 是否依赖另一个技能 |
| --- | --- | --- | --- |
| [产品六视图完整安装包](product-six-views.zip) | 一张产品图 | 正、左、右、后、顶、底六张独立图片 | 否 |
| [产品参考海报完整安装包](product-reference-posters.zip) | 前面的参考海报＋最后六张独立产品视图 | 每张参考对应一张独立产品海报，并统一名称、型号和文案 | 否，已有六视图即可单独使用 |

六视图指六个独立图片文件，每张仅一个视角，不是一张六宫格。需要从单张产品图一路做到海报时，安装两个技能并按下文连续使用。

## 安装前：确认宿主能力

技能是工作流程与提示词，不包含图像模型、API 密钥或自动安装图像工具的程序。安装成功与能够实际出图是两件事。

宿主需要能够：

- 加载本地技能，读取 `SKILL.md` 及其引用文件。
- 查看上传的产品图和参考图，并将原图传给可用的图像生成/编辑工具。
- 分别生成图片、查看结果并针对问题编辑，保存和交付独立图片文件。

参考海报通常涉及一张参考图加六张产品图；单次参考图数量不足时，应按技能规则分步生成与编辑，覆盖全部六视图，不能静默丢弃图片或改用六宫格。

若当前宿主没有可用的图像工具，应明确说明无法实际出图；提示词和文案只能标为替代交付，不能声称已生成图片，也不应静默切换外部付费 API。具体附件限制、工具可用性和输出分辨率以当前宿主为准。

## 单独安装或同时安装

1. 按需下载一个或两个完整安装包：
   - [直接下载产品六视图](https://github.com/HH683/product-visual-skills/raw/refs/heads/main/product-six-views.zip)
   - [直接下载产品参考海报](https://github.com/HH683/product-visual-skills/raw/refs/heads/main/product-reference-posters.zip)
2. 解压每个 ZIP，找到与技能同名的文件夹。复制整个文件夹，保留 `SKILL.md`、`agents/` 和 `references/`；不要只复制 `SKILL.md`，也不要把 ZIP 原样放进技能目录当作已安装。
3. 将技能文件夹放入宿主实际加载的个人技能目录。当前 [Codex 官方技能文档](https://learn.chatgpt.com/docs/build-skills)列出的个人目录为 `~/.agents/skills/`（Windows：`%USERPROFILE%\.agents\skills\`）。若你现有环境已使用并能识别 `~/.codex/skills/`，可沿用该环境的有效目录；避免在多处重复安装同名技能。
4. 检查最终路径是 `<技能目录>/product-six-views/SKILL.md` 或 `<技能目录>/product-reference-posters/SKILL.md`，不要多套一层同名目录。更新旧版本时，先备份自己的修改，再替换对应技能文件夹。
5. 在技能列表或输入 `$` 后确认能够找到相应技能。若未出现，检查目录层级、文件是否完整及技能是否启用，再尝试重启 Codex。能够识别技能后，用下文示例验证实际出图能力。

同时安装时，两份文件夹应并列放置，不要把一个技能放进另一个技能中。Windows 示例：

```text
%USERPROFILE%\.agents\skills\
├── product-six-views/
│   ├── SKILL.md
│   ├── agents/openai.yaml
│   └── references/generation.md
└── product-reference-posters/
    ├── README.md
    ├── SKILL.md
    ├── agents/openai.yaml
    └── references/generation.md
```

### 首次安装检查清单

- [ ] 已下载所需的独立技能 ZIP，而非把整个仓库压缩包当成一个技能安装。
- [ ] 每个技能目录下可直接找到 `SKILL.md`，没有多余的外层文件夹。
- [ ] `agents/openai.yaml` 和 `references/generation.md` 均已保留，引用文件可读取。
- [ ] 宿主能识别技能，也能读取图片、调用图像工具并交付文件。
- [ ] 六视图测试得到六张独立图片；海报测试得到与参考数量对应的独立图片。仅识别到技能或返回提示词，不算出图验证通过。

## 单独使用：产品六视图

上传一张产品图，输入：

```text
使用 $product-six-views，生成正、左、右、后、顶、底六张独立产品图，并检查3C产品的必要接口和按键。
```

输出顺序为正视、正左侧、正右侧、后视、顶视、底视。默认左右按从正面看产品的观察者左右区分。文件通常命名为 `01-front`、`02-left`、`03-right`、`04-rear`、`05-top`、`06-bottom`，扩展名保留实际格式。

保留原图可确认结构；对不可见的后面、底部、接口等以最少假设补全，并说明哪些是推定。3C 检查不代表每件产品都应新增 USB-C 或实体电源键；供电和操作方式应结合图中证据与已知功能判断。生成图不能代替实物测绘或精确工程图。若要求完全符合实物且不允许推定，应提供可靠资料或补充视图。

## 单独使用：产品参考海报

已有同一产品的六张独立视图时，可只安装本技能。

按顺序上传：**先放参考海报，再放产品正、左、右、后、顶、底六张独立图片**。至少需要一张参考和六张产品图，共七张。以本次明确的上传顺序为准，不依赖文件名自动排序。输入：

```text
使用 $product-reference-posters，逐张匹配前面参考海报的构图、排版与审美。最后六张是同一产品的正、左、右、后、顶、底独立六视图，请统一名称、型号和文案，实际生成对应海报。
```

例如：3 张参考海报＋6 张产品图，共 9 张输入，生成 3 张独立海报，参考 01→海报 01、参考 02→海报 02、参考 03→海报 03。各张分别跟随对应参考，不混成通用模板。

已有名称和型号优先保留；缺省时可以统一创作，并在交付中说明为创作命名。每换一款产品，都重新读取六视图、建立结构记录与文案，不继承上一款的接口、名称或规格。

## 连续使用：一张产品图 → 六视图 → 参考海报

1. 安装两个技能，先用 `$product-six-views` 处理原产品图。
2. 查看六张独立结果，确认同一产品的比例、配色、接口与按键位置一致，左右和顶底没有互换。记录交付说明中的重要推定；有缺图或明显结构冲突时先补齐、修正。
3. 保存六张最终图片。在海报任务中重新明确分组：先上传本次参考海报，再按正、左、右、后、顶、底上传六张最终产品图。即使沿用同一聊天，也要说明本批图片的顺序；跨聊天时重新附上图片和推定说明。
4. 调用 `$product-reference-posters`，并传递上一阶段的推定说明和已确认资料。生成六视图并不使推定结构变成实物事实，海报不能把推定的接口或功能写成已验证卖点。
5. 按参考顺序验收独立海报，检查产品结构、名称型号、中文文字和事实依据；保存到本次产品的独立目录，避免覆盖上一款。

可在海报指令末尾补充：

```text
六视图来自上一阶段生成，请保留其推定说明。推定结构仅用于视觉一致性，不作为已确认功能或规格宣传；未提供的产品参数不要编造。
```

## 产品信息与文案边界

- **可确认信息**：原图可见外观、用户明确确认的信息或可靠产品资料。外观呈现金属质感，不等于已确认金属材质；画出了接口，也不能据此推出传输速度或快充功率。
- **推定结构**：不可见面的补全、推定的接口类型或位置、转面推演，需说明证据状态，不能称为原厂结构或实测结果。
- **创作文案**：缺少名称、型号时可统一拟定，但应说明为本次创作，不冒充真实注册品牌或原厂型号。
- **未知规格**：不编造续航、尺寸、重量、功率、容量、防水等级、认证、价格、销量、奖项、医疗功效或专利；不照搬参考海报的品牌、参数、网址或二维码。无依据的参数模块可用名称、类别词或已知外观特征适配，不能为填满版面制造规格。

若必须使用准确原厂参数，应先提供可核对的资料；无法确认的内容省略或说明未知。

## 仓库结构与压缩包内容

仓库根目录当前发布的是说明文件和两个独立安装包：

```text
product-visual-skills/
├── README.md
├── product-six-views.zip
└── product-reference-posters.zip
```

每个 ZIP 内只有对应的技能文件夹，解压后分别为：

```text
product-six-views.zip
└── product-six-views/
    ├── SKILL.md
    ├── agents/openai.yaml
    └── references/generation.md

product-reference-posters.zip
└── product-reference-posters/
    ├── README.md
    ├── SKILL.md
    ├── agents/openai.yaml
    └── references/generation.md
```

`SKILL.md` 是执行规则；`agents/openai.yaml` 提供展示名称和默认调用提示；`references/generation.md` 是生成与修复提示词骨架。海报包内的 `README.md` 是该技能的独立说明。

完整规则以各安装包内的 `SKILL.md` 为准；仓库首页负责安装和串联说明。

## 维护者发布检查清单

以下项目用于每次发布自查，未勾选不代表本次已执行测试。

### 打包与内容核对

- [ ] 根目录包含 `README.md` 和两个名称准确的 ZIP，首页下载链接指向对应文件。
- [ ] 逐个解压两个 ZIP，核对上面的文件清单；顶层各为一个同名技能文件夹，无重复嵌套、缺失文件或混入另一个技能。
- [ ] `SKILL.md` 的 `name`、文件夹名与 `agents/openai.yaml` 的默认调用名一致；名称、描述和示例没有串包。
- [ ] `references/generation.md` 等相对引用可从各自的 `SKILL.md` 正常找到；海报包独立 README 与首页规则一致。
- [ ] 从本次最终源文件重新打包，再解压比对内容；没有混入旧版本、密钥、临时生成图或个人路径等无关文件。

### 安装与使用验证

- [ ] 在干净的技能目录中分别安装每个 ZIP，确认各自可识别、可独立调用；再确认同时安装时两者均可用。
- [ ] 用一张产品图验证六张独立视图的方向、结构和文件交付，并检查推定是否明确披露。
- [ ] 用一张参考＋六张独立产品图验证一张海报；再用多张参考验证逐张对应、总数正确。

- [ ] 检查缺图、顺序冲突和当前宿主参考图数量限制；无法实际出图时，明确说明限制和替代交付。
- [ ] 检查海报没有继承参考中的未知参数或上一款产品信息，创作名称/型号已注明，中文无明显错误。
- [ ] 发布后从 GitHub 实际下载两个 ZIP 并重新解压，确认下载内容与本次待发布文件一致；记录未通过或未执行的验证及其限制。
